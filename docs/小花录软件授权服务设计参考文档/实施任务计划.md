> 本文档由 `集成到memos实施方案.md` v2.0 派生，任务编号 T01~T25；每个任务包含前置依赖、直接后继、实现上下文、子任务和验收标准。
> 当前状态：T01 已完成（2026-10-26），参数已冻结并落到 `internal/license/constants.go`；T02 起待开始。

## Context

本计划依据 `docs/小花录软件授权服务设计参考文档/集成到memos实施方案.md` v2.0，把方案拆成可以逐项提交、逐项验证的开发任务。目标是在 memos 进程内实现一套严格一对一、首次激活锁定到期、客服手动续期、客户端接口统一挂在 `/xiaohualu` 下的授权服务，不改动小花录客户端代码。

**已冻结的 V1 口径**（来自实施方案 §13，默认值如下；T01 会再次确认并落到常量/文档）：

- 一张卡密最多绑定一台设备，一台设备同时最多绑定一张卡密；无 `max_devices`。
- `plan` 只是标签，`duration_days` 才是权威有效期：`daily/monthly/yearly` 允许 1~3650 任意天数（UI 预填 1/30/365），`lifetime` 固定 0；创建接口不再强制 plan 与天数一一对应。
- 非 `lifetime` 卡密首次激活时 `expires_at = 激活时间 + duration_days`，之后不重算；`lifetime` 无到期时间。
- 首次激活写入 `bound_device_id`；客户端没有解绑 UI，契约保留 `deactivate` 端点；换机走管理端“释放设备”，释放才清除锁定。
- 续期由客服设置绝对到期时间（RFC3339 UTC），新值必须晚于 `max(now, 当前 expires_at)`；不再使用“延长 N 天”。
- 未激活卡密不会过期；过期卡密可设置未来到期时间恢复；过期令牌 + 已延长卡密可通过 refresh 恢复。
- 客户端接口前缀 `/xiaohualu`；管理接口 `/admin/api/license`。
- 创建卡密不生成 CSV，网页展示并复制；更新包保留当前 + 上一版。
- 单实例、单密钥，不做多副本和密钥轮换。
- 上述参数统一由 `internal/license/constants.go` 提供，后续任务只引用该文件。

**执行规则**

- 每个顶层任务是一个可独立提交/PR 的工作单元；任务内的子任务是同一 PR 内的步骤。
- 定义完成（DoD）：代码 + 单元测试/集成测试 + 相关 lint 通过；涉及迁移时三库同步；涉及前端时 `pnpm lint && pnpm test`。
- 不修改 `proto/`，不手改生成文件；不新增 `acl_config.go` 条目。
- 所有 Go 错误按仓库约定使用 `github.com/pkg/errors`；原生 Echo handler 使用 v5 的 `func(c *echo.Context) error`。
- 本地启动前必须有 `.env`（`cmd/memos/main.go` 缺失 `.env` 会 panic）。
- 任务编号 `T01`~`T25`，子任务 `Txx.y`。T01 是唯一根任务，T25 是唯一终端任务；其余任务均有前置依赖和直接后继，无孤立任务。

## 风险与回滚

- **数据模型风险**：`license_bindings` 的两个唯一约束是严格一对一的最终防线；任何迁移调整都必须三库同步，并在升级库上验证。
- **到期计算风险**：`expires_at` 只在首次激活写入；任何重算都会造成无限续期。相关改动必须跑 T07/T09 的回归。
- **续期风险**：refresh 的“已延长卡密 + 过期令牌”例外是关键恢复路径；改动 refresh 时必须保留该测试。
- **前缀风险**：`/xiaohualu`、`/admin` 必须加入 `shouldSkipFrontendStatic`；否则接口返回 HTML，客户端表现为 JSON 解析失败。
- **部署风险**：单实例、单密钥；512 MiB 上传需要反代配置；`.env` 缺失会 panic；私钥文件权限 0600。
- **回滚**：每个任务独立提交；若某阶段失败，回退该任务提交即可，迁移文件不跨任务修改。
