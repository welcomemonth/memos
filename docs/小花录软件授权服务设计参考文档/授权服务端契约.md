# 授权服务端契约

> 版本：1.0（2026-10-24）
> 适用：客户端 `internal/license` 与独立授权服务端（Go 项目，不在本仓库）。服务端实现蓝图见 `docs/授权服务端设计.md`。
> 本阶段只定契约，服务端实现与卡密签发（T-56，改为服务端管理页面承担，不做 CLI）在服务端仓库完成。

## 1. 总体约定

- 所有接口只接受 `POST`/`GET`，请求与响应均为 `application/json; charset=utf-8`。
- 生产环境必须通过 HTTPS 部署；客户端只允许 `https://`，`http://` 仅用于本机回环地址（开发/联调）。
- 客户端超时 15 秒；失败不重试、不阻塞 UI，由后台每日刷新重试。
- 请求日志、错误日志、监控中**不得**出现明文卡密、令牌或设备指纹。
- 服务端时间以 UTC 为准，时间字段使用 Unix 秒；`update.json` 的时间字段使用 RFC3339。
- 客户端通过环境变量 `XHL_LICENSE_SERVER` 覆盖服务端地址（默认空 = 授权服务未配置）；该变量只影响客户端，不改变契约。

## 2. 接口

### 2.1 `POST /v1/activate`

首次激活或同设备重复激活。

请求：

```json
{
  "key": "XHL-XXXX-XXXX-XXXX-XXXX",
  "deviceId": "3f2c9d8a1b7e4f60a5c3d2e1f0b9a876",
  "appVersion": "0.1.0",
  "os": "windows"
}
```

成功 `200`：

```json
{
  "token": "eyJ2IjoxLCJzdWIiOi... .MEUCIQ...",
  "status": "active"
}
```

失败：见第 4 节错误码。

语义：

- **幂等**：相同 `key` + 相同 `deviceId` 重复激活直接返回新签发的令牌（同一到期时间），不额外占用设备名额。
- 设备数上限由卡密的 `max_devices` 决定；新设备在已满时返回 `409 device_limit`，不得顶掉旧设备。
- 卡密已过期返回 `403 card_expired`；已撤销返回 `403 revoked`。
- 每次成功激活写 `bindings.last_seen_at`；令牌中的 `sub` 必须等于请求的 `deviceId`。

### 2.2 `POST /v1/refresh`

客户端启动、每日刷新、检测到时钟回拨时调用。

请求：

```json
{
  "token": "<当前令牌>",
  "deviceId": "3f2c9d8a1b7e4f60a5c3d2e1f0b9a876",
  "appVersion": "0.1.0"
}
```

成功 `200`：

```json
{
  "token": "<新令牌>",
  "status": "active"
}
```

语义：

- 服务端必须验签、校验 `sub == deviceId`、校验绑定仍然有效。
- 新令牌的 `plan`、`exp` 与旧令牌一致，`iat` 更新为服务端当前时间，`nonce` 重新生成。
- 到期返回 `401 token_expired`；撤销/解绑返回 `403 revoked`；令牌无效/签名错误返回 `401 invalid_token`。
- 刷新不改变到期时间，不延长有效期。

### 2.3 `POST /v1/deactivate`

用户主动解绑当前设备（V1 客户端不提供入口，保留给客服工具与后续版本）。

请求：

```json
{
  "token": "<当前令牌>",
  "deviceId": "3f2c9d8a1b7e4f60a5c3d2e1f0b9a876"
}
```

成功 `200`：

```json
{ "status": "ok" }
```

语义：

- 删除绑定并把该令牌的 `nonce` 加入撤销集合；重复调用幂等返回 `200`。
- 解绑后该令牌的 `refresh` 必须失败（`403 revoked`）。

### 2.4 `GET /v1/health`

```json
{ "status": "ok", "time": 1761264000 }
```

用于客户端诊断与部署探活；不需要鉴权。

### 2.5 `GET /v1/update/windows.json`

静态文件，用于 T-70 检查更新：

```json
{
  "latestVersion": "1.2.0",
  "releaseNotes": "- 修复已知问题\n- 新增功能",
  "downloadUrl": "https://download.example.com/xiaohualu-1.2.0.exe",
  "publishedAt": "2026-10-24T08:00:00Z",
  "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
}
```

字段全部必填；`downloadUrl` 必须是 HTTPS；`sha256` 为安装包 SHA-256 小写十六进制。

## 3. 令牌格式

紧凑格式，无 JWT 头：

```text
base64url(payload) + "." + base64url(signature)
```

- `signature = Ed25519.Sign(privateKey, []byte(base64url(payload)))`。
- `payload` 为 UTF-8 JSON，base64url 使用无填充（RawURLEncoding）。
- 签名为 64 字节，base64url 无填充。
- 客户端只内置**公钥**；私钥只存在于服务端部署环境，绝不进入客户端、仓库或日志。
- 客户端启动时用内置公钥验签；验签失败、字段非法、设备不匹配、已过期都视为无效，不信任任何未签名字段。

`payload`：

```json
{
  "v": 1,
  "sub": "3f2c9d8a1b7e4f60a5c3d2e1f0b9a876",
  "plan": "yearly",
  "iat": 1761264000,
  "exp": 1792800000,
  "nonce": "9tK3xQm2c8Wv1s0p"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `v` | int | 固定 `1` |
| `sub` | string | 绑定的设备 ID（32 位小写十六进制） |
| `plan` | string | `daily` / `monthly` / `yearly` / `lifetime`，不得为 `trial` |
| `iat` | int64 | 签发时间，Unix 秒，必须 > 0 |
| `exp` | int64 | 到期时间，Unix 秒，必须 > `iat`；`lifetime` 固定为 `0` |
| `nonce` | string | 随机串（建议 16 字节 base64url），用于撤销与审计 |

## 4. 错误码

统一响应体：

```json
{ "code": "device_limit", "message": "该卡密已在其他设备激活" }
```

| HTTP | code | 客户端展示 | 说明 |
|---|---|---|---|
| 400 | `bad_request` | 请求无效 | JSON/字段缺失或格式错误 |
| 401 | `invalid_key` | 卡密无效，请检查后重试 | 卡密不存在或哈希不匹配 |
| 401 | `invalid_token` | 授权信息无效，请重新激活 | 验签失败/令牌结构损坏 |
| 401 | `token_expired` | 授权已过期，请续费后重新激活 | 令牌到期 |
| 403 | `card_expired` | 卡密已过期 | 卡密自身有效期结束 |
| 403 | `revoked` | 授权已被撤销，请联系客服 | 卡密/绑定/令牌被撤销 |
| 403 | `device_mismatch` | 设备不匹配，请使用原设备或联系客服 | 令牌与设备不一致 |
| 409 | `device_limit` | 该卡密已绑定其他设备 | 超过 `max_devices` |
| 429 | `rate_limited` | 操作过于频繁，请稍后再试 | 限流 |
| 500 | `internal` | 授权服务暂时不可用 | 未分类服务端错误 |

客户端对网络错误、超时、非 JSON 响应统一映射为“无法连接授权服务器，请检查网络或代理”。

## 5. 服务端数据模型（建议）

```sql
-- 卡密。只存哈希，明文仅在签发时出现一次。
CREATE TABLE cards (
    id             TEXT PRIMARY KEY,
    key_hash       TEXT NOT NULL UNIQUE,   -- SHA-256(规范化卡密)
    plan           TEXT NOT NULL,          -- daily/monthly/yearly/lifetime
    duration_days  INTEGER NOT NULL,       -- lifetime 为 0
    max_devices    INTEGER NOT NULL DEFAULT 1,
    revoked        INTEGER NOT NULL DEFAULT 0,
    expires_at     TEXT NOT NULL DEFAULT '', -- 卡密自身有效期，空 = 不过期
    created_at     TEXT NOT NULL
);

CREATE TABLE bindings (
    card_id       TEXT NOT NULL,
    device_id     TEXT NOT NULL,
    activated_at  TEXT NOT NULL,
    last_seen_at  TEXT NOT NULL,
    token_nonce   TEXT NOT NULL,
    PRIMARY KEY (card_id, device_id)
);

CREATE TABLE revocations (
    nonce      TEXT PRIMARY KEY,
    reason     TEXT NOT NULL,
    revoked_at TEXT NOT NULL
);
```

要求：

- 卡密规范化：去除首尾空白、转大写后再做 SHA-256；客户端不需要知道规范化规则。
- `duration_days` 只用于首次激活计算 `exp`；`lifetime` 的 `exp = 0`。
- 激活事务需同时写 `bindings` 与刷新 `last_seen_at`，避免并发超额。
- 解绑删除 `bindings` 并把当前令牌 `nonce` 写入 `revocations`。

## 6. 语义与安全要求

- **激活幂等**：同设备重复激活必须返回同一到期时间的新令牌。
- **设备上限**：按 `bindings` 行数判断；超过返回 `409`，不做“自动踢掉旧设备”。
- **到期判断**：以服务端 `exp` 为准；客户端本地只做展示和宽限判断。
- **撤销**：卡密撤销、绑定删除、令牌 `nonce` 入撤销集合；refresh 必须拒绝已撤销令牌。
- **限流**：建议每 IP、每设备 10 次/分钟；命中返回 `429`。
- **时钟**：服务端不得信任客户端时间；所有签发/校验使用服务端时钟。
- **密钥管理**：Ed25519 私钥只保存在服务端密钥管理系统；建议按年轮换，并保留旧公钥一个宽限期。

## 7. 客户端行为（与契约对应）

- 激活成功：验签 → 校验 `sub == deviceId` → DPAPI 缓存令牌 → 记录 `last_verified_at`。
- 启动与每日 refresh；首次刷新失败时记录 `grace_started_at`（持久化），此后 1 小时内继续 `active`，超过则 `expired`；刷新成功立即清除宽限。宽限从失败时刻起算，避免每日刷新把在线用户误判为过期。
- 令牌被篡改、设备不匹配、`exp` 已过、refresh 返回 `revoked`：立即 `expired`，不进入宽限。
- 时钟回拨（本地时间比 `last_seen_at` 倒退超过 5 分钟）：要求在线 refresh；失败则 `expired`。
- 试用 3 天，试用开始时间与最近活跃时间均 DPAPI 加密存储；试用过期与会员过期走同一闸门。
- 客户端错误提示使用上表中的中文文案；原始错误码只写日志。

### 7.1 设备指纹

- Windows 读取注册表 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` 与系统盘卷序列号，拼接固定应用盐后做 SHA-256，取前 16 字节输出 32 位小写十六进制。
- 不采集用户名、IP、MAC 或其他个人信息；原始标识不落库、不写日志。
- 读取失败时生成 16 字节随机 ID，用 DPAPI 加密保存到 `app_state`，此后重启保持不变。
- 更换系统盘、重装系统会改变硬件指纹；旧令牌因 `sub` 不匹配而失效，需要重新激活或联系客服解绑。

## 8. 契约测试

`internal/license/contract_test.go` 中的 fake server 按本契约实现以下场景：

1. 首次激活：令牌可验签，`sub` 等于设备 ID。
2. 同设备重复激活：不增加绑定数，返回有效令牌。
3. 换设备且 `max_devices = 1`：`409 device_limit`。
4. 卡密已过期：`403 card_expired`。
5. 卡密撤销：激活 `403 revoked`；已有令牌 refresh 失败。
6. 刷新：返回同一 `exp`、新 `iat`/`nonce` 的令牌。
7. 篡改令牌：客户端验签失败，refresh 返回 `401 invalid_token`。
8. `GET /v1/health`：返回 `ok`。

服务端实现完成部署后，用同一组场景做真实联调回归；不需要修改客户端代码。
