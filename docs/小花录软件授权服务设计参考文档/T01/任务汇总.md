## 2. 口径冻结结果

| 项目 | 定稿口径 | 说明 |
|---|---|---|
| 卡密与设备 | 严格一对一；`license_bindings.device_id` 主键 + `card_id` UNIQUE | 无 `max_devices` |
| `durationDays` 与 plan | `duration_days` 是权威有效期；plan 只是标签 | `daily/monthly/yearly` 允许 1~3650 任意天数（UI 预填 1/30/365）；`lifetime` 固定 0 |
| 有效期 | 非 lifetime 首次激活时 `expires_at = 激活时间 + duration_days`，之后不重算 | 未激活卡密不会过期 |
| 卡密锁定 | 首次激活写入 `bound_device_id` | 客户端没有解绑 UI；换机走管理端释放 |
| 客户端解绑 | 契约保留 `/v1/deactivate`；保留 `bound_device_id` | 同设备可重激活且沿用原到期时间 |
| 管理端释放 | 允许对任意卡密操作 | 删除绑定、撤销 nonce、清空 `bound_device_id`；到期时间不变 |
| 客服续期输入 | 绝对到期时间 `expiresAt`（RFC3339 UTC） | 新值必须晚于 `max(now, 当前 expires_at)`；只更新 `expires_at` |
| 过期卡密延长 | 允许 | 设置一个未来时间即可恢复 |
| 过期令牌 refresh | 允许恢复 | 卡密 `expires_at` 仍在未来时，不返回 `token_expired`，直接签发新令牌 |
| 更新包 | 保留当前版 + 上一版 | 最多两个 `.exe` |
| `XHL_UPDATE_BASE_URL` | 包含 `/xiaohualu` | 客户端 `XHL_LICENSE_SERVER` 也包含该前缀，再追加 `/v1/...` |
| 部署 | 单实例、单密钥 | 内存限流 + 本地更新包目录；不做轮换/多副本 |

- 恢复真实 lint 基线的安全做法（需用户确认，且要求工作区没有已跟踪文件的未提交修改）：
  ```bash
  git config --local core.autocrlf input
  git checkout-index -a -f   # 从索引重写工作区为 LF；会覆盖所有已跟踪文件
  ```
  本次没有执行，因为该操作会全量重写工作区，权限分类器拒绝了该命令。

## 7. 可能存在的问题 / 风险

1. **绝对到期时间的产品语义**：本次定为“必须晚于 `max(now, 当前 expires_at)`”，即只能延长、不能缩短。如果客服需要“改短”或按自然日（而不是精确时间）设置，需要在 T08 实现前再确认。UI 用日期选择器时，建议统一发 `23:59:59Z` 或明确时区，避免“到期日当天不能用”的歧义。
2. **时区**：接口统一 RFC3339 UTC，前端日期控件需要做本地时区转换；如果直接拼接 `YYYY-MM-DD`，会出现 8 小时偏差。
3. **plan 与 durationDays 解耦**：列表、统计、导出、令牌里的 `plan` 只是标签；任何展示有效期的逻辑都必须读 `duration_days`/`expires_at`，不能再用 `plan` 推算天数。后续 T15 的校验和 T21 的表格需要注意。
4. **客户端解绑端点**：客户端 UI 没有解绑入口，但契约保留 `/v1/deactivate`。如果后续决定完全删除该端点，需要同步修改客户端 `API` 接口；当前保留不会影响客户端。
5. **测试密钥与生产密钥**：`xhl.key` 是本地测试密钥，公钥 `wOr6DtVm...` 与客户端内置 `DefaultServerPublicKey` 不同。联调、生产必须成对替换；私钥文件不要提交，生产建议 0600 且使用独立部署密钥。
6. **`.env` 硬依赖**：`cmd/memos/main.go` 的 `init()` 在缺少 `.env` 时直接 panic；新环境必须先复制 `.env.example`。
7. **Milvus 硬依赖**：即使只做授权服务，`cmd/memos` 也会先初始化 Milvus；本地没有 Milvus 就无法启动。T25 端到端验证前必须先解决。
8. **前端 lint 基线**：当前 `pnpm lint` 不是绿色；T19~T24 的前端改动会叠加在这些既有问题上。建议在 T19 前单独清理，或至少用 `biome check` 只检查新增文件。
9. **Windows 文件锁**：T10 的更新包删除/覆盖在 Windows 上可能遇到文件被占用；方案已约定降级为 warning，实现时需要测试。
10. **常量命名与后续扩展**：`constants.go` 目前只有 T01 冻结项；T02 会补 `errors.go`/`config.go`。不要在 T02 重复声明同名常量或包注释，直接引用/扩展本文件。
11. **未配置私钥的行为**：T02 才实现“未配置私钥时服务正常启动、客户端接口除 health 外返回 500”；T01 只生成了本地密钥，尚未验证该行为。
