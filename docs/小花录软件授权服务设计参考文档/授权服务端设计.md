# 授权服务端设计

> 版本：1.2（2026-10-25，历史参考）
> 依据：`docs/授权服务端契约.md` v1.0；客户端 `internal/license` 已按契约 + fake server 完成（T-58~T-61）。
> **注意：本文档是“独立 Go 仓库 + Gin + 独立 SQLite + 独立管理页”的历史设计蓝图。服务已改为合并进 memos，实际实现以 `集成到memos实施方案.md` v2.0 为准。** 主要差异：Echo v5 而非 Gin；复用 memos 主库、ADMIN 认证和设置页；客户端路由挂载在 `/xiaohualu`；严格一卡一设备（无 `max_devices`）；首次激活锁定到期、客服手动延长；不提供 keygen；创建卡密不导出 CSV；单实例、单密钥。
>
> 下面保留独立服务版本的工程细节，供理解原始契约和迁移参考；与实施方案冲突时，以实施方案为准。

## 1. 决策记录

| 决策项 | 结论 |
|---|---|
| 仓库位置 | **独立 Go 仓库**（如 `xhl-license-server`），不进客户端仓库，不参与 Wails 构建。本地可用父目录并列两个仓库（VS Code 多根工作区）降低多仓库管理成本 |
| 技术栈 | Go 1.24.x + Gin；SQLite（`modernc.org/sqlite`）；前端管理页独立 React 小应用 |
| 卡密管理 | 服务端内置**管理页面**（React + pnpm 构建后 `go:embed` 嵌入），只能在此创建/管理卡密；不做 CLI |
| HTTPS | 服务端只实现 HTTP；生产用宝塔面板反代终止 TLS |
| 管理员认证 | 单管理员账号 + Session cookie（SQLite 存 session） |

## 2. 关键结构决策

- 服务端是独立 Go module（`module xhl-license-server`，自带 `go.mod`），与客户端仓库完全解耦。
- 不 import 客户端 `xiaohualu/internal/license`（跨仓库也不可行）。紧凑令牌格式由契约定义，在 `internal/token` 自包含实现（签发 + 验签，约 100 行，与客户端 `internal/license/token.go` 逻辑对齐，以契约为准）。契约 §8 的 8 组场景会在服务端侧用 httptest 真实回归一遍。
- 时间一律存 RFC3339 UTC 文本（与契约 §5 SQL 一致）；对外时间字段用 Unix 秒。
- 私钥来源：env `XHL_PRIVATE_KEY`（base64）或私钥文件路径 env `XHL_PRIVATE_KEY_FILE`；配套 `cmd/keygen` 生成 Ed25519 密钥对（私钥写文件 0600，打印公钥供客户端替换 `internal/license/token.go` 的 `DefaultServerPublicKey` 占位值，对应客户端 R-M6-1）。

## 4. 客户端接口实现要点（契约 §2，逐条）

| 路由 | 行为要点 |
|---|---|
| `POST /xiaohualu/v1/activate` | 规范化哈希卡密 → 查卡（不存在 401 `invalid_key`）→ 撤销 403 `revoked` → 卡过期 403 `card_expired` → 同事务查绑定：同设备幂等返回新令牌（exp 不变，仅 iat/nonce 更新 + `last_seen_at`）；同一张卡已绑定其他设备返回 409 `device_limit`；首次激活写 `activated_at`/`expires_at = now + duration_days`/`bound_device_id`（lifetime 的 `expires_at` 为空），`sub=deviceId` |
| `POST /xiaohualu/v1/refresh` | 验签失败 401 `invalid_token`；nonce 在撤销集合或绑定不存在 403 `revoked`；`sub != deviceId` 403 `device_mismatch`；正常令牌到期 401 `token_expired`；卡自身过期 403 `card_expired`；客服延长后返回新 exp（过期令牌 + 已延长卡密允许恢复）；成功更新 `token_nonce`/`last_seen_at` |
| `POST /xiaohualu/v1/deactivate` | 删绑定 + nonce 入 `revocations`；保留 `bound_device_id`，同设备可重激活，其他设备仍 409；幂等返回 `{status:"ok"}` |
| `GET /xiaohualu/v1/health` | `{status:"ok",time:<unix秒>}`，UTC |
| `GET /xiaohualu/v1/update/windows.json` | 从 `UPDATE_DIR` 读静态文件返回；字段缺失/`downloadUrl` 非 HTTPS 时启动报错拒绝服务 |

- 统一错误体 `{code,message}`（中文 message），状态码与契约 §4 表一一对应；`bad_request` 覆盖 JSON/字段非法。
- **限流**：手写每 IP 令牌桶（map+mutex，简单可靠），`/v1/*` 10 次/分钟，命中 429 `rate_limited`。
- **日志脱敏**：slog 只记 card id / 请求路径 / 状态码，绝不记明文卡密、令牌、设备指纹原文。

## 5. 管理端设计（不在客户端契约内）

> 集成版本使用 memos 的 ADMIN 认证和设置页，不再有独立登录/session。以下接口形态以实施方案为准。

- **认证**：集成版本调用 memos 的 `AuthenticateToUser`，`ADMIN` 角色可访问；不再使用独立管理员账号/session。
- **接口**：
  - `GET /admin/api/license/cards?page=&pageSize=&status=` — 分页列表（返回哈希/套餐/状态/首次激活/到期/锁定设备，无明文）
  - `POST /admin/api/license/cards/lookup` — 按卡密哈希精确查找（卡密走 body）
  - `POST /admin/api/license/cards` — `{plan,count,duration_days}`，生成卡密，**明文仅在本次响应出现一次**；不导出 CSV；每张卡密固定只能绑定一台设备
  - `POST /admin/api/license/cards/:id/revoke` — 撤销卡密
  - `POST /admin/api/license/cards/:id/extend` — `{days}`，客服续期，延长 `expires_at`
  - `GET /admin/api/license/cards/:id/bindings` — 查看绑定/锁定设备
  - `POST /admin/api/license/bindings/unbind` — `{cardId, deviceId}`，客服释放设备（删绑定 + nonce 入撤销集合 + 清 `bound_device_id`）
- **前端**：集成进 memos 的 Settings admin section，不单独维护 React 应用；创建结果在网页展示并复制，不下载 CSV。

## 6. 配置（历史参考）

> 集成版本配置以《集成到memos实施方案》§7 为准：只用 `XHL_*` 环境变量，复用 memos 的数据库和 ADMIN 认证，没有 `PORT`/`DB_PATH`/`ADMIN_USERNAME`/`ADMIN_PASSWORD`。

独立服务版本的配置为：`PORT`(8080)、`DB_PATH`(data/license.db)、`XHL_PRIVATE_KEY` 或 `XHL_PRIVATE_KEY_FILE`、`ADMIN_USERNAME`/`ADMIN_PASSWORD`、`UPDATE_DIR`、`XHL_TRUST_PROXY`(反代后取真实 IP 用)。

## 7. 实现顺序（历史参考）

> 集成版本的实施顺序见《集成到memos实施方案》§9 与 §12.2；以下是独立服务版本的 TDD 顺序。



1. **骨架**：`go.mod`、config、storage（建表迁移）、`cmd/server` 起 gin + `/v1/health`（测试：配置解析、迁移幂等、health 响应）。
2. **token + cardkey**：紧凑令牌签发/验签、卡密规范化与生成（测试：roundtrip、篡改、各 base64 形态、格式校验）。
3. **license service**：Activate/Refresh/Deactivate 全语义（测试：sqlite `:memory:`，覆盖契约 §8 场景 1~7 的领域层：幂等、一卡一设备、卡过期、撤销、刷新换 nonce 同 exp、解绑后 refresh 失败）。
4. **api handler**：gin 路由、错误码映射、请求校验、限流中间件（测试：httptest 全错误码、bad_request、429、health）。
5. **契约回归测试**：用 httptest 起完整服务端，把客户端 `internal/license/contract_test.go` 的 8 组场景跑真实 HTTP 回归。
6. **update.json**：静态文件伺服 + 启动校验（测试：缺字段/非 HTTPS 拒绝、正常返回）。
7. **admin 后端**：login/session、卡密 CRUD、解绑（测试：未登录 401、创建只回一次明文、撤销后激活 403、解绑后 refresh revoked）。
8. **cmd/keygen**：密钥对生成（测试：生成→签名→验签闭环）。
9. **admin 前端** `web/`：页面与接口接线，`go:embed` 伺服（验证：登录→建卡→列表→撤销流程可走通）。
