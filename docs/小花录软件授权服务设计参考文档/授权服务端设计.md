# 授权服务端设计

> 版本：1.1（2026-10-24）
> 依据：`docs/授权服务端契约.md` v1.0；客户端 `internal/license` 已按契约 + fake server 完成（T-58~T-61）。
> 本文档是授权服务端的实现蓝图，**不绑定具体仓库**——服务端是独立 Go 仓库（建议名 `xhl-license-server`，module 名同名），拿走本文档即可开工。对外契约以契约文档为准，本文档只描述工程实现，不改变任何客户端可见行为。

## 1. 决策记录

| 决策项 | 结论 |
|---|---|
| 仓库位置 | **独立 Go 仓库**（如 `xhl-license-server`），不进客户端仓库，不参与 Wails 构建。本地可用父目录并列两个仓库（VS Code 多根工作区）降低多仓库管理成本 |
| 技术栈 | Go 1.24.x + Gin；SQLite（`modernc.org/sqlite`）；前端管理页独立 React 小应用 |
| 卡密管理 | 服务端内置**管理页面**（React + pnpm 构建后 `go:embed` 嵌入），只能在此创建/管理卡密；不做 CLI |
| HTTPS | 服务端只实现 HTTP；生产用宝塔面板反代终止 TLS |
| 管理员认证 | 单管理员账号 + Session cookie（SQLite 存 session） |

## 2. 关键结构决策

- 服务端是独立 Go module（`module xhl-license-server`，自带 `go.mod`），与客户端仓库完全解耦。
- 不 import 客户端 `xiaohualu/internal/license`（跨仓库也不可行）。紧凑令牌格式由契约定义，在 `internal/token` 自包含实现（签发 + 验签，约 100 行，与客户端 `internal/license/token.go` 逻辑对齐，以契约为准）。契约 §8 的 8 组场景会在服务端侧用 httptest 真实回归一遍。
- 时间一律存 RFC3339 UTC 文本（与契约 §5 SQL 一致）；对外时间字段用 Unix 秒。
- 私钥来源：env `XHL_PRIVATE_KEY`（base64）或私钥文件路径 env `XHL_PRIVATE_KEY_FILE`；配套 `cmd/keygen` 生成 Ed25519 密钥对（私钥写文件 0600，打印公钥供客户端替换 `internal/license/token.go` 的 `DefaultServerPublicKey` 占位值，对应客户端 R-M6-1）。

## 3. 目录结构

```
xhl-license-server/
├── go.mod                      # module xhl-license-server（gin、modernc.org/sqlite）
├── cmd/
│   ├── server/main.go          # 读配置 → 开库 → 迁移 → 起 gin
│   └── keygen/main.go          # 生成 Ed25519 密钥对
├── internal/
│   ├── config/config.go        # env 配置：PORT/DB_PATH/私钥/管理员账号/UPDATE_DIR
│   ├── token/token.go          # 紧凑 Ed25519 令牌签发/验签（契约 §3）
│   ├── cardkey/cardkey.go      # 卡密规范化(Trim+ToUpper+SHA-256)与 XHL-XXXX 生成
│   ├── storage/storage.go      # sqlite 打开/WAL/迁移；cards/bindings/revocations 建表
│   ├── license/service.go      # 领域逻辑：Activate/Refresh/Deactivate（事务）
│   ├── api/handler.go          # /v1/* 客户端接口 + 错误码映射 + 限流中间件
│   ├── admin/admin.go          # /admin/api/* 管理接口 + session 认证 + 卡密 CRUD
│   └── session/session.go      # SQLite 存 session（admin_sessions 表），HttpOnly cookie
├── web/                        # 管理页 React 小前端（Vite + React + TS strict）
│   └── dist/                   # pnpm build 产物，go:embed 进二进制
└── migrations/（或内嵌 storage） # 建表 SQL
```

## 4. 客户端接口实现要点（契约 §2，逐条）

| 路由 | 行为要点 |
|---|---|
| `POST /v1/activate` | 规范化哈希卡密 → 查卡（不存在 401 `invalid_key`）→ 撤销 403 `revoked` → 卡过期 403 `card_expired` → 同事务查绑定：同设备幂等返回新令牌（exp 不变，仅 iat/nonce 更新 + `last_seen_at`）；新设备超 `max_devices` 返回 409 `device_limit`；首次激活 exp = now + duration_days（lifetime=0），`sub=deviceId` |
| `POST /v1/refresh` | 验签失败 401 `invalid_token`；nonce 在撤销集合或绑定不存在 403 `revoked`；`sub != deviceId` 403 `device_mismatch`；令牌到期 401 `token_expired`；卡自身过期 403 `card_expired`；成功签发 plan/exp 不变、新 iat/nonce 的令牌，更新 `token_nonce`/`last_seen_at` |
| `POST /v1/deactivate` | 删绑定 + nonce 入 `revocations`；幂等返回 `{status:"ok"}` |
| `GET /v1/health` | `{status:"ok",time:<unix秒>}`，UTC |
| `GET /v1/update/windows.json` | 从 `UPDATE_DIR` 读静态文件返回；字段缺失/`downloadUrl` 非 HTTPS 时启动报错拒绝服务 |

- 统一错误体 `{code,message}`（中文 message），状态码与契约 §4 表一一对应；`bad_request` 覆盖 JSON/字段非法。
- **限流**：手写每 IP 令牌桶（map+mutex，简单可靠），`/v1/*` 10 次/分钟，命中 429 `rate_limited`。
- **日志脱敏**：slog 只记 card id / 请求路径 / 状态码，绝不记明文卡密、令牌、设备指纹原文。

## 5. 管理端设计（不在客户端契约内）

- **认证**：`POST /admin/api/login`（用户名/密码来自 env，常数时间比较），成功签发 32 字节随机 session token 存 `admin_sessions` 表（带过期时间），HttpOnly cookie。其余 `/admin/api/*` 走鉴权中间件，未登录 401。
- **接口**：
  - `GET /admin/api/cards?page=&q=` — 分页列表（只回哈希/套餐/状态/设备数，无明文）
  - `POST /admin/api/cards` — `{plan,count,max_devices,duration_days,expires_at}`，生成卡密，**明文仅在本次响应出现一次**，支持 CSV 导出
  - `POST /admin/api/cards/:id/revoke` — 撤销卡密
  - `GET /admin/api/cards/:id/bindings` — 查看绑定
  - `DELETE /admin/api/bindings/:cardId/:deviceId` — 客服解绑（删绑定 + nonce 入撤销集合，与契约客户端文案“联系客服”对应）
- **前端** `web/`：Vite + React 19 + TS strict（独立 `package.json`，pnpm），无状态库（局部 useState 足够），构建产物 `web/dist` 用 `go:embed` 嵌入，gin 在 `/admin/*` 伺服。页面：登录、卡密列表（搜索/分页/撤销）、创建卡密（批量 + 结果展示 + CSV 下载）、绑定查看与解绑。

## 6. 配置（env，均有默认值）

`PORT`(8080)、`DB_PATH`(data/license.db)、`XHL_PRIVATE_KEY` 或 `XHL_PRIVATE_KEY_FILE`、`ADMIN_USERNAME`/`ADMIN_PASSWORD`、`UPDATE_DIR`、`XHL_TRUST_PROXY`(反代后取真实 IP 用)。

## 7. 实现顺序（每步 TDD：先写失败测试）

1. **骨架**：`go.mod`、config、storage（建表迁移）、`cmd/server` 起 gin + `/v1/health`（测试：配置解析、迁移幂等、health 响应）。
2. **token + cardkey**：紧凑令牌签发/验签、卡密规范化与生成（测试：roundtrip、篡改、各 base64 形态、格式校验）。
3. **license service**：Activate/Refresh/Deactivate 全语义（测试：sqlite `:memory:`，覆盖契约 §8 场景 1~7 的领域层：幂等、设备上限、卡过期、撤销、刷新换 nonce 同 exp、解绑后 refresh 失败）。
4. **api handler**：gin 路由、错误码映射、请求校验、限流中间件（测试：httptest 全错误码、bad_request、429、health）。
5. **契约回归测试**：用 httptest 起完整服务端，把客户端 `internal/license/contract_test.go` 的 8 组场景跑真实 HTTP 回归。
6. **update.json**：静态文件伺服 + 启动校验（测试：缺字段/非 HTTPS 拒绝、正常返回）。
7. **admin 后端**：login/session、卡密 CRUD、解绑（测试：未登录 401、创建只回一次明文、撤销后激活 403、解绑后 refresh revoked）。
8. **cmd/keygen**：密钥对生成（测试：生成→签名→验签闭环）。
9. **admin 前端** `web/`：页面与接口接线，`go:embed` 伺服（验证：登录→建卡→列表→撤销流程可走通）。

## 8. 验证

```bash
go vet ./... && go test ./...          # 全量单测（含契约回归）
go build ./cmd/server                  # 单二进制
# 手工冒烟：
XHL_PRIVATE_KEY_FILE=... go run ./cmd/server &
curl -X POST localhost:8080/v1/activate -d '{"key":"...","deviceId":"...","appVersion":"0.1.0","os":"windows"}'
curl localhost:8080/v1/health
# 管理页：pnpm build && 打开 /admin 走 登录→建卡→激活 全链路
```

最终闭环：服务端生成的公钥替换客户端 `internal/license/token.go` 的 `DefaultServerPublicKey` 占位值后，客户端可对本服务端完成真实激活（部署阶段再做）。
